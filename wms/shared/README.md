# shared

DTO, доменные типы-значения и контракты API, общие для `core` и `planner`.

Подключается обоими сервисами как обычная зависимость времени компиляции. Контракт описан **один раз**, дублирования DTO нет, рассогласование ловится компилятором, а не в рантайме (§12.2). Здесь же будут типы запросов и ответов планировщика из §12.4.

| Пакет | Содержимое |
| --- | --- |
| `marking` | `LocationCode` — адрес ячейки с контрольным символом; `QrPayload` — разбор QR с префиксами `LOC:`, `SKU:`, `CNT:`, `TSK:`, `WRK:` (§11.3) |

Сообщения об ошибках разбора кодов пишутся так, чтобы их можно было показать сборщику как есть: в них сказано, что сделать (NFR-U-05).
