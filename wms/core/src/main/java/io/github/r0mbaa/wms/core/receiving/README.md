# core/receiving — M3. Приёмка и размещение

Документ прихода, приёмка по факту в зону приёмки, рекомендация ячейки и размещение двумя сканированиями с записью в журнал движений.

**Требования:** FR-M3-01 .. FR-M3-07. **Процесс:** §6.2.

## Процесс

| Шаг | Запрос | Что происходит |
| --- | --- | --- |
| 1. Ожидаемая поставка (FR-M3-01) | `POST /api/v1/receipts` | Документ со строками «товар × ожидаемое количество». Номер — от поставщика или внутренний `PR-000001` |
| 2. Приёмка по факту (FR-M3-02) | `POST …/{number}/received` | Движение `RECEIPT` в `WH-RECEIVING`. Товар не из документа принимается строкой с нулевым ожиданием, чтобы излишек попал в расхождения |
| 3. Рекомендация (FR-M3-03) | `GET …/{number}/recommendation?sku=&quantity=` | Ячейка по правилу ниже |
| 4. Размещение (FR-M3-06) | `POST …/{number}/putaway` | Два скана и количество → движение `PUTAWAY` из зоны приёмки в ячейку |
| 5. Закрытие | `POST …/{number}/close` | Строки с расхождениями «принято − ожидалось» в ответе и в аудите |

Права: `RECEIVER` и `WAREHOUSE_ADMIN`.

## Размещение двумя сканированиями

Кладовщик сканирует QR товара, затем QR полки и вводит количество. Количество не выводится из числа сканирований, потому что QR кодирует вид товара, а не экземпляр (FR-M3-06a). Сканы распознаются по префиксу (`SKU:`, `LOC:`). Код без префикса проверяется как адрес ячейки, затем как штрихкод или артикул, затем как код виртуального места.

Обратный порядок «полка, потом товар» принимается. В ответе тогда `orderReversed = true`, а в `recognized` сказано, что именно распознано (FR-M3-06).

Размещение не в рекомендованную ячейку допустимо (FR-M3-05): ответ содержит `deviation = true`, а в комментарии движения остаётся рекомендованная ячейка.

После закрытия документа принимать товар по нему нельзя, но принятое и ещё не размещённое можно разместить.

## Правило рекомендации

`PutawayAdvisor` — это простое правило, а не исследуемый алгоритм. Слоттинг по ABC и совместной встречаемости (M12) позже заменит его.

1. Ячейка, где этот SKU уже лежит (консолидация), если выдержит добавку.
2. Иначе пустая ячейка отбора или навала, ближайшая к депо по манхэттенской метрике, а для SKU класса C — самая дальняя, чтобы ближние места оставались ходовому товару.

Ячейка всегда активна, не заблокирована, принимает класс хранения, выдержит вес и вместит объём. В зоне с выделенным местом правило не создаёт второе место того же SKU (INV-08). Разные SKU в одну ячейку не рекомендуются, хотя фактическое размещение это допускает.

Кросс-докинг (FR-M3-07, приоритет W) не реализован.
