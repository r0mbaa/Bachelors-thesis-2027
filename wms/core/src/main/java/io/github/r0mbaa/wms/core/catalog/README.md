# core/catalog — M2. Номенклатура

Справочник SKU: наименование, единица измерения, габариты, вес, объём, класс хранения, штрихкоды, QR вида товара.

**Требования:** FR-M2-01 .. FR-M2-06.

- **SKU — вид товара, а не экземпляр.** QR товара кодирует артикул (`SKU:85123A`), поэтому количество при сканировании вводится вручную (FR-M3-06a). Артикул без пробелов, иначе его не закодировать в QR.
- **Несколько штрихкодов на SKU** (FR-M2-03): EAN-13, Code128, внутренний. Каждый штрихкод однозначно указывает на один SKU, иначе скан на приёмке был бы неоднозначен. У EAN-13 проверяется контрольная цифра, чтобы опечатка ручного ввода не завела лишний код.
- **Распознавание кода** (`GET /api/v1/skus/resolve?code=`): QR системы, штрихкод производителя или артикул. Приёмка работает и с заводской упаковкой без наклеенного QR.
- **Объём** по умолчанию считается как Д × Ш × В, для товара неправильной формы задаётся явно.
- **Класс хранения** (FR-M2-04): `NORMAL`, `FRAGILE`, `HEAVY`, `OVERSIZED`. С ним сверяется ограничение ячейки (`PUT /api/v1/locations/{code}/storage-classes`, FR-M1-06). Пустое ограничение означает, что ячейка принимает любой класс.
- **ABC и XYZ** (FR-M2-05) хранятся в карточке и будут рассчитываться по истории отборов вместе со слоттингом (M12). Пока истории нет, их задаёт вручную `WAREHOUSE_ADMIN` или `ANALYST` (`PUT /api/v1/skus/{article}/classes`) — для подготовки сценариев заполнения по ABC.
- Альтернативные единицы измерения (FR-M2-06, приоритет C) не реализованы: все количества ведутся в базовой единице.

Изменения карточки и штрихкодов пишутся в аудит со старым и новым значением (NFR-SEC-03). Чтение доступно всем ролям, изменение — `WAREHOUSE_ADMIN`.
