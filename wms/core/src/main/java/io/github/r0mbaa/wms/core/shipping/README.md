# core/shipping — M11. Отгрузка и документы

Консолидация собранного по заказам и отгрузка со списанием со склада.

**Требования:** FR-M11-01 .. FR-M11-07. **Инварианты:** INV-07, INV-09.

## Путь собранного

```mermaid
flowchart LR
    cell[Ячейка] -- PICK --> cnt[Тара WH-CNT-…]
    cnt -- TRANSFER, консолидация --> ship[Зона отгрузки WH-SHIPPING]
    ship -- SHIP --> out((Отгружено))
```

Со склада товар списывается только движением `SHIP` (FR-M11-05, FR-M10-11). Поэтому остаток мест тары и зоны отгрузки всегда равен отобранному, но не отгруженному по строкам заказов (INV-09). Вручную эти места не меняются: перемещения, корректировки и списания разрешены только для ячеек и зоны приёмки.

| Запрос | Что делает | Роль |
| --- | --- | --- |
| `POST /api/v1/shipping/tasks/{number}/consolidate` | Содержимое тары завершённого задания переходит в зону отгрузки, тара освобождается, заказы получают `PACKED` (FR-M11-01) | `SHIPPER`, `DISPATCHER` |
| `POST /api/v1/shipping/orders/{number}/ship` | Отгружает собранное по заказу; недособранное возвращается списком `shortages` и пишется в аудит (FR-M11-06) | `SHIPPER` |
| `GET /api/v1/shipping/integrity` | Сверка INV-09 по SKU | `WAREHOUSE_ADMIN`, `ANALYST` |

Отгрузка возможна только без активных резервов по заказу (INV-07). Это соблюдается само собой: при сборке каждый резерв закрывается.

## Отложено

- Печатные формы в PDF и XLSX (FR-M11-03, FR-M11-04). Для PDF с кириллицей нужен встроенный шрифт; сокращённый вариант §15.4 требует только маршрутный лист.
- Контрольная проверка заказа сканированием перед упаковкой (FR-M11-02, урезана в §3.2).
- Выгрузка данных об отгрузке во внешнюю систему (FR-M11-07, приоритет C).
