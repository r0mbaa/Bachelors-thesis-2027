# core/inventory — M4. Остатки, движения, инвентаризация

Остатки по парам «место × SKU», неизменяемый журнал движений, ручные операции и проверка целостности учёта.

**Требования:** FR-M4-01 .. FR-M4-10. **Инварианты:** INV-01, INV-02, INV-04, INV-08 (§11.2).

## Единая точка изменения

Остаток меняет только `StockLedger`. Каждая проводка — это запись журнала и согласованное изменение строк остатка в одной транзакции (FR-M4-03, NFR-R-01). Поэтому остаток всегда восстановим из журнала (INV-04), и другие модули (приёмка, задания, отгрузка) пишут движения тем же путём.

Порядок захвата блокировок фиксирован, чтобы встречные перемещения не заблокировали друг друга взаимно:

1. строка ячейки-приёмника (`FOR NO KEY UPDATE`, не мешает вставкам движений со ссылкой на неё): два одновременных размещения разных товаров не превысят вместимость вдвоём;
2. строка зоны, если в ней выделенное место: два размещения одного SKU в разные ячейки не пройдут оба;
3. строки остатка по возрастанию id места.

Приёмник, в который физически кладут товар (приход, размещение, перемещение, возврат), проверяется: ячейка активна, не заблокирована (FR-M1-11), принимает класс хранения товара (FR-M1-06), выдержит вес и вместит объём. В зоне с выделенным местом SKU не может лежать в двух ячейках (INV-08). Это проверяется уже после проводки, поэтому перенос всего товара из ячейки в ячейку допустим.

Расход берётся только из свободной части остатка: зарезервированное под заказы не перемещается и не списывается.

## Что держит сама БД

| Инвариант | Механизм |
| --- | --- |
| INV-01, INV-02 | `CHECK (quantity >= 0 AND reserved_quantity >= 0)` и `CHECK (reserved_quantity <= quantity)` |
| Направление движения по типу | `CHECK`: приход только приходит, отгрузка и списание только уходят, корректировка — в одну сторону |
| Неизменяемость журнала (NFR-R-04) | Триггер `BEFORE UPDATE OR DELETE` отвергает изменение. В отличие от отзыва прав у прикладной роли, он действует и для владельца таблицы |

## Инварианты, которые может нарушить топология

`InventoryGuards` слушает события `LayoutSaved` и `RowsAssignedToZone`. Слушатели выполняются синхронно в транзакции изменения, и исключение отменяет изменение целиком:

- новая версия планировки не может убрать ячейку, в которой лежит товар (FR-M15-03c);
- ряды не переводятся в зону с выделенным местом, если товар окажется в ней в нескольких ячейках (INV-08).

Так пакеты `topology` и `layout` не зависят от пакета остатков.

## API

| Запрос | Роль |
| --- | --- |
| `GET /api/v1/locations/{code}/stock`, `/skus/{article}/stock`, `/warehouses/{wh}/stock` | любая |
| `GET /api/v1/skus/{article}/movements`, `/locations/{code}/movements` — история (FR-M4-05) | любая |
| `POST /api/v1/inventory/placements` — товар сразу в ячейку, минуя приёмку (FR-M15-13) | `WAREHOUSE_ADMIN`, `RECEIVER` |
| `POST /api/v1/inventory/transfers` — перемещение (FR-M4-09, FR-M15-15) | `WAREHOUSE_ADMIN`, `RECEIVER`, `DISPATCHER` |
| `POST /api/v1/inventory/adjustments` — привести учёт к факту пересчёта | `WAREHOUSE_ADMIN` |
| `POST /api/v1/inventory/write-offs` — списание с причиной | `WAREHOUSE_ADMIN` |
| `GET /api/v1/inventory/integrity` — сверка остатков с журналом (INV-04, FR-M4-06) | `WAREHOUSE_ADMIN`, `ANALYST` |

Товар и место принимаются в том виде, в каком их отсканировали или ввели: QR (`SKU:…`, `LOC:…`), штрихкод, артикул, код ячейки. Введённый вручную адрес ячейки сверяется по контрольному символу, поэтому опечатка отличается от несуществующей ячейки.

## Массовое заполнение склада

`POST /api/v1/warehouses/{wh}/fill` (FR-M15-16, `WAREHOUSE_ADMIN`) раскладывает товары по пустым ячейкам отбора, каждый в свою ячейку, как при выделенном месте хранения. Нужно для подготовки сценариев: одни и те же заказы на складе, заполненном по разным правилам, показывают вклад размещения отдельно от вклада алгоритмов (FR-M14-11).

| Правило | Порядок ячеек |
| --- | --- |
| `RANDOM` | Случайный с зерном `seed` (NFR-E-01): одно зерно — одна раскладка |
| `ABC` | Товары по классу A → B → C → без класса; ячейки по расстоянию от депо по графу склада, при равенстве — ближе к «золотой зоне» по высоте (1,0 м, §8.1) |

Количество на ячейку ограничено её вместимостью по весу и объёму. Товары, которые уже есть на складе, пропускаются, иначе в зоне с выделенным местом появилось бы второе место (INV-08). `dryRun=true` показывает раскладку, ничего не проводя. Поступление проводится обычным `RECEIPT` через `StockLedger`, поэтому журнал и сверки остаются целыми.

Корреляционное правило требует матрицы совместной встречаемости и появится вместе со слоттингом (M12).

## Отложено

- Партии и сроки годности (FR-M4-10, приоритет W): колонок в схеме нет, добавятся миграцией, когда до них дойдёт очередь.
- Выборочная и циклическая инвентаризация (FR-M4-07, FR-M4-08) урезаны до ручной корректировки с причиной (§3.2, §15.4).
