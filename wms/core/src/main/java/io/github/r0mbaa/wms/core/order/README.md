# core/order — M5. Заказы и волны

Заказы на отгрузку, их строки, объединение в волны, дедлайны.

**Требования:** FR-M5-01 .. FR-M5-08.

## Заказ

Заказ (FR-M5-01) содержит номер, контрагента, приоритет от 1 до 9, дедлайн отгрузки, перевозчика, направление и строки «товар × количество». Таблица называется `customer_order`, потому что `order` — зарезервированное слово SQL.

Статусная модель (FR-M5-03): `NEW → ALLOCATED → PLANNED → IN_PROGRESS → PICKED | PARTIALLY_PICKED → PACKED → SHIPPED`, а также `CANCELLED`. Модули аллокации, заданий и отгрузки двигают статус только через `CustomerOrder.transition` с явным списком допустимых исходных статусов.

CHECK на строке заказа не даёт зарезервировать, отобрать или отгрузить больше заказанного (INV-06).

| Запрос | Что делает | Роль |
| --- | --- | --- |
| `POST /api/v1/orders` | Приём заказа по API (FR-M5-02) | `DISPATCHER`, `WAREHOUSE_ADMIN` |
| `POST /api/v1/orders/import?warehouse=` | Импорт CSV, целиком или никак (FR-M5-02) | `DISPATCHER`, `WAREHOUSE_ADMIN` |
| `GET /api/v1/orders?warehouse=&status=`, `/orders/{number}` | Списки и карточка | любая |
| `GET /api/v1/orders/{number}/coverage` | Обеспеченность строк остатками (FR-M5-04) | любая |
| `POST /api/v1/orders/{number}/cancel` | Отмена до начала сборки (FR-M5-07) | `DISPATCHER`, `WAREHOUSE_ADMIN` |

Формат CSV — одна строка файла на строку заказа, разделитель `;` или `,`:

```
number;counterparty;priority;deadline;carrier;direction;sku;quantity
SO-1;ООО Ромашка;7;2026-10-20T18:00:00+03:00;СДЭК;Север;85123A;2
```

Ошибка в любой строке отменяет импорт всего файла, а в сообщении указан номер строки.

**Отмена** публикует событие `OrderCancelled` в той же транзакции. Резервы снимает модуль аллокации, строки неначатых заданий — модуль заданий. Пакет заказов от них не зависит.

## Волны

`POST /api/v1/waves` (FR-M5-05) отбирает новые заказы вне волн по критериям: дедлайн не позже, перевозчик, направление, приоритет не ниже, максимальный размер волны (по умолчанию 50). Сначала идут заказы с ближайшим дедлайном, затем с большим приоритетом. Критерии сохраняются вместе с волной, чтобы потом было видно, почему в неё попали именно эти заказы.

Кандидаты блокируются на запись (`FOR NO KEY UPDATE`), поэтому два диспетчера, формирующие волны одновременно, не заберут один заказ дважды.

Срочный заказ (`hot`, FR-M5-08) в волну не попадает, это же ограничение держит CHECK в БД.

Автоматическое формирование волны по расписанию (FR-M5-06, приоритет S) пока не реализовано.
