# core/admin — M13. Администрирование

Аутентификация, RBAC по ролям §5, журнал аудита. Справочник тары и конфигурация планировщика появятся вместе с заданиями и планировщиком.

**Требования:** FR-M13-01 .. FR-M13-05, NFR-SEC-01 .. 04.

## Вход и токены

| Запрос | Что делает |
| --- | --- |
| `POST /api/v1/auth/login` | Имя и пароль → JWT доступа (15 мин) и токен обновления (12 ч, примерно смена) |
| `POST /api/v1/auth/refresh` | Токен обновления → новая пара. Старый токен после обмена недействителен |
| `POST /api/v1/auth/logout` | Отзыв токена обновления |
| `GET /api/v1/auth/me` | Текущий пользователь и его роли |

Токены выпускает и проверяет сам `core`, поэтому подпись симметричная (HS256): внешнего сервера авторизации нет. Ключ задаётся через `WMS_JWT_SECRET`, пустое значение означает случайный ключ на каждый запуск.

Токен обновления хранится в БД только в виде SHA-256. Если уже обменянный токен предъявляют повторно, значит, его копия есть у кого-то ещё, и все сессии пользователя отзываются. Смена пароля и блокировка пользователя тоже завершают его сессии.

Пароли хранятся в bcrypt с префиксом алгоритма (`{bcrypt}…`), поэтому алгоритм можно сменить без миграции (NFR-SEC-04).

## Роли

| Роль | §5 |
| --- | --- |
| `RECEIVER` | Кладовщик приёмки |
| `PICKER` | Сборщик |
| `DISPATCHER` | Диспетчер, начальник смены |
| `SHIPPER` | Оператор отгрузки |
| `WAREHOUSE_ADMIN` | Администратор склада |
| `ANALYST` | Аналитик, исследователь |
| `SYSTEM_ADMIN` | Системный администратор |

Права на операции объявлены в контроллерах через `@PreAuthorize`, а `SecurityConfig` задаёт только границу «открыто или нужен вход». Администратор не может снять с себя роль `SYSTEM_ADMIN` или заблокировать себя, чтобы в системе не остаться без администратора.

Первый администратор создаётся при запуске на пустой БД, если задан `WMS_ADMIN_PASSWORD`. Пароля по умолчанию нет.

## Аудит

`AuditLog.record(...)` пишет, кто, что, когда сделал, а также старое и новое значение в JSONB (NFR-SEC-03). Запись идёт в транзакции самого изменения: если изменение откатилось, записи о нём тоже нет. Движения остатков в аудит не дублируются, потому что их журнал ведётся отдельно и неизменяем сам по себе. Просмотр: `GET /api/v1/audit?entityType=&entityId=`.
