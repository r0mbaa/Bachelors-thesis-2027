# layout — геометрия склада

Чистая Java-библиотека без Spring и БД. Из планировки, которую пользователь редактирует на виде сверху, выводит всё остальное: ячейки с кодами и координатами, а затем граф склада. Используется конструктором в `core`, планировщиком через `planner-engine` и стендом `research`, поэтому живёт отдельно от сервисов (см. «Отступления от спецификации» в [`wms/README.md`](../README.md)).

| Пакет | Содержимое | Требования |
| --- | --- | --- |
| `model` | `Layout`, `RackRow`, `RackProfile`: документ планировки | FR-M15-02, FR-M15-03, FR-M15-10 |

| `graph` *(следующий шаг)* | Построение графа: точки отбора, узлы пересечений, депо | FR-M1-07, FR-M15-06, §8.7 |

## Принятые решения по геометрии

- **Ряд — цепочка секций**, секции могут быть разных профилей (FR-M15-03a). Секции разной глубины выравниваются по лицевой линии ряда: сборщик подходит к лицевой стороне, и она должна быть прямой.
- **Поворот ряда только на 90°** (`Facing`). Под другим углом проходы перестают быть параллельны осям, и ломается манхэттенская метрика (§8.7, Д2).
- **Нумерация секций и позиций от начала координат склада**, а не от депо (§8.7, В1).
- **Координата `z` ячейки — высота полки над полом**, а не номер яруса. Номера ярусов разных профилей физически несопоставимы, поэтому штраф `h(z)` считается от высоты (§8.1).
- **`Layout` проверяет только ссылочную целостность** (уникальность номеров рядов и профилей, ссылки на профили). Ошибки планировки, которые пользователь исправляет на плане, собирает валидатор в виде списка замечаний, а не исключением.
