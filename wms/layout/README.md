# layout — геометрия склада

Чистая Java-библиотека без Spring и БД. Из планировки, которую пользователь редактирует на виде сверху, выводит всё остальное: ячейки с кодами и координатами, а затем граф склада. Используется конструктором в `core`, планировщиком через `planner-engine` и стендом `research`, поэтому живёт отдельно от сервисов (см. «Отступления от спецификации» в [`wms/README.md`](../README.md)).

| Пакет | Содержимое | Требования |
| --- | --- | --- |
| `model` | `Layout`, `RackRow`, `RackProfile`: документ планировки; `StandardProfiles` — пять типовых профилей | FR-M15-02, FR-M15-03, FR-M15-03d, FR-M15-10 |
| `cells` | `CellGenerator`: ячейки с кодами, координатами `(x, y, z)`, объёмом и допустимой нагрузкой | FR-M15-05, FR-M1-03, FR-M1-04, FR-M1-06 |
| `graph` | `GraphBuilder`: граф склада — депо, точки отбора, пересечения, рёбра вдоль осей с длиной в метрах | FR-M1-07, FR-M15-06, §8.7 |
| `validation` | `LayoutValidator`: границы, пересечения, ширина прохода перед каждой лицевой стороной, депо, связность по графу; замечания с местом на плане | FR-M15-07 |
| `classification` *(следующий шаг)* | `SINGLE_BLOCK_RECTANGULAR` / `MULTI_BLOCK` / `GENERAL_GRAPH` | FR-M15-08, §8.7 Г1–Г2 |
| `wizard` | Параметрический генератор прямоугольной планировки — общий для мастера и стенда | FR-M15-09, FR-M14-01 |

## Принятые решения по геометрии

- **Ряд — цепочка секций**, секции могут быть разных профилей (FR-M15-03a). Секции разной глубины выравниваются по лицевой линии ряда: сборщик подходит к лицевой стороне, и она должна быть прямой.
- **Поворот ряда только на 90°** (`Facing`). Под другим углом проходы перестают быть параллельны осям, и ломается манхэттенская метрика (§8.7, Д2).
- **Нумерация секций и позиций от начала координат склада**, а не от депо (§8.7, В1).
- **Координата `z` ячейки — высота полки над полом**, а не номер яруса. Номера ярусов разных профилей физически несопоставимы, поэтому штраф `h(z)` считается от высоты (§8.1).
- **Вместимость ячейки выводится из профиля**: объём — ширина ячейки × глубина × высота её яруса, допустимая нагрузка — нагрузка на ярус, поделённая поровну между ячейками яруса.
- **`Layout` проверяет только ссылочную целостность** (уникальность номеров рядов и профилей, ссылки на профили). Ошибки планировки, которые пользователь исправляет на плане, собирает валидатор в виде списка замечаний, а не исключением.

## Мастер типовой планировки

`RectangularLayoutWizard` строит склад по числу проходов, числу поперечных проходов, секциям в ряду блока, профилю, ширине прохода и поперечного прохода и положению депо. Поперёк склада повторяется шаг `d = w_a + 2·w_r`: ряд лицом к проходу, проход, ряд лицом к проходу; соседние проходы разделены парой рядов спина к спине, крайние ряды стоят у стен. Передний и задний поперечные проходы есть всегда, депо стоит на оси переднего.

`RectangularLayoutParameters.shapeFactor()` даёт коэффициент формы `k = L / d` (§8.1). Именно его, а не три размера по отдельности, варьирует эксперимент (§14.2).

## Граф склада

`GraphBuilder.build(layout)` выводит граф `G = (V, E, w)` (§8.1) из планировки. Параметры — `w_merge` (2,5 м) и `w_min` (1,2 м) в `GraphSettings`.

| Задача §8.7 | Решение |
| --- | --- |
| А1. Объединять ли стены прохода | Проход не шире `w_merge` — одна линия точек на оси, общая для обеих стен; шире — линия у каждой стены в `w_merge / 2` от неё |
| А2. Несовпадение секций | Сетка отметок вдоль прохода от начала координат склада, отметки обеих стен совпадают |
| А3. Несколько ячеек в секции | Секция не шире `w_merge` — одна точка на все её ячейки и ярусы (колонка стеллажа, §1.5); шире — точка на ячейку |
| Б1, Б3, Б5. Что считать проходом | Проходимость по факту, без предположения о регулярности: ходить можно там, где до стеллажа не меньше `w_min / 2` |
| Д1, Д2. Сетка или граф | Разреженный граф по осям, координаты точные (до миллиметра), рёбра только вдоль осей |

**Уточнение А2.** Шаг отметок `d_mark` — не наименьшая ширина секции, а наименьшее расстояние между соседними точками: ширина секции для узких секций и ширина ячейки для широких. Иначе широкая секция, разбитая по ячейкам (А3), снова сжалась бы в одну-две отметки. На складе из одних полок это та же ширина секции.

**Как строится.** Кандидаты в оси движения — линии через точки отбора и депо и средние линии всех «полос» между соседними краями стеллажей. Для прямоугольных препятствий такие линии содержат кратчайший путь по осям. Узлы — точки отбора, депо и пересечения линий в свободном пространстве; рёбра соединяют соседние узлы на линии, если между ними нет стеллажа. Затем удаляются тупиковые пересечения и промежуточные узлы на прямых отрезках. Повороты остаются: по ним маршрут разворачивается в ломаную для схемы (FR-M8-05).

Номера узлов детерминированы: депо — 0, затем точки отбора, затем пересечения, каждая группа по возрастанию координат. `WarehouseGraph.pickPoints` отображает каждую ячейку в её точку отбора.

**Размер и скорость.** Склад в 21 600 ячеек (12 проходов, 3 блока) даёт граф из 721 узла; построение занимает 30–60 мс после прогрева и 260 мс при холодном старте JVM (NFR-P-08: не более 500 мс).

**Проверки.** Кроме примеров с точными расстояниями, jqwik на случайных типовых планировках проверяет три свойства: каждая точка отбора достижима из депо; каждая ячейка отображается в точку перед своей лицевой стороной не дальше `d_mark` вдоль ряда и `w_merge / 2` поперёк; путь из депо не короче манхэттенского расстояния, т.е. граф не срезает углы через стеллажи.

## Валидация

`LayoutValidator.validate(layout)` возвращает все замечания списком: пользователь исправляет их за один проход по плану. У каждого замечания есть область на плане для подсветки, номера затронутых рядов и текст с указанием, что сделать.

| Замечание | Условие |
| --- | --- |
| `OUT_OF_BOUNDS` | Габарит ряда выходит за склад |
| `OVERLAP` | Габариты рядов пересекаются с положительной площадью; ряды спина к спине допустимы |
| `AISLE_TOO_NARROW` | Полоса глубиной `w_min` перед лицевой стороной занята стеллажом или выходит за стену (§8.7, Б2) |
| `DEPOT_BLOCKED` | Депо за границами склада, внутри ряда или ближе `w_min / 2` к нему |
| `UNREACHABLE` | До точек отбора ряда нет пути от депо. Для узких рядов не выдаётся, чтобы не дублировать причину |
| `EMPTY` | Предупреждение: на плане нет стеллажей |

Связность проверяется по тому же графу, по которому потом строятся маршруты, а не по отдельной растровой сетке (§8.7, Д1). Поэтому «достижимо для валидатора» и «достижимо для планировщика» — одно и то же.
