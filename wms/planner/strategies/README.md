# planner/strategies — реестр алгоритмов

Каждое семейство реализует свой интерфейс стратегии; все реализации собираются контейнером Spring автоматически (§12.3).

| Пакет | Модуль §7 | Каталог методов |
| --- | --- | --- |
| [`routing/`](routing) | M8 Маршрутизация | §9.1 |
| [`batching/`](batching) | M7 Батчинг | §9.2 |
| [`dispatch/`](dispatch) | M9 Диспетчеризация | §9.3 |
| [`allocation/`](allocation) | M6 Аллокация | §8.4 |
| [`slotting/`](slotting) | M12 Слоттинг и аналитика | §9.4 |

**Отступление от §12.1.** Спецификация перечисляет здесь четыре пакета: `routing/`, `batching/`, `dispatch/`, `allocation/`. Пакет `slotting/` добавлен под M12, потому что §12.4 относит `POST /api/v1/analytics/slotting` к контракту именно этого сервиса, а §9.4 описывает слоттинг как такое же семейство взаимозаменяемых методов.

Метод `supports(LayoutClass)` в сочетании с классификатором топологии (FR-M15-08) позволяет системе сообщить, какие алгоритмы применимы к построенной пользователем планировке.
